# 同意が不明なとき、誰が連絡を再開できるか — 停止・再開権限の研究

- 研究日: 2026-10-27 朝 JST
- 段階: research / candidate。経典昇格なし。
- 継続元: [10月26日夜・謝罪反復と接触停止](./2026-10-26-evening-repeated-apology-contact-boundaries.md)
- 中心の問い: 接触同意が unknown のとき、善意の再送と必要な安全通知をどう分離し、誰が停止解除を判断するか。

## 1. 出典とその射程

**初期仏教（一次資料）**: MN 58（アバヤ王子経）は発言の真実性・利益・適切な時機を区別する。MN 61（ラーフラへの教え）は身体・言葉・心の行為を前・中・後に省察する。いずれも現代の個人情報・通知権限の法規を直接規定しない。

- MN 58: https://suttacentral.net/mn58/en/sujato
- MN 61: https://suttacentral.net/mn61/en/sujato

**世俗哲学（一次資料）**: J. S. Mill『自由論』第4章は個人の自由と他者への害の境界を論じる。本人の意思を軽視した善意の介入を批判的に点検する材料となるが、あらゆる通知を禁止する命題ではない。

- https://en.wikisource.org/wiki/On_Liberty/Chapter_4

**制度資料（宗教教義とは別）**: 国連経済社会理事会決議2002/12の基本原則7・9・10・13は、修復的司法の参加に自由意思による同意・撤回可能性・安全・力関係の配慮を求める。刑事司法の修復手続に関する原則であり、あらゆる私的連絡に直接適用される法律ではない。

- UNODCの解説: https://www.unodc.org/e4j/en/crime-prevention-criminal-justice/module-8/key-issues/1--concept--values-and-origin-of-restorative-justice.html
- 決議原文の所在: https://www.refworld.org/legal/resolution/ecosoc/2002/27056

**AIリスク管理（任意の実務枠組み）**: NIST AI RMF 1.0（2023年）は Govern / Map / Measure / Manage によりリスクを管理する枠組み。以下の状態機械はNISTの規定そのものではなく、本研究の独自設計候補。

- https://www.nist.gov/publications/artificial-intelligence-risk-management-framework-ai-rmf-10

## 2. 研究上の区別

- **連絡の同意**: allowed / refused / unknown / withdrawn。未返信や既読を allowed と推定しない。
- **連絡目的**: apology / ordinary_followup / contractual_notice / safety_notice。目的を混ぜない。
- **通知根拠**: 法令・契約・明示同意・正当な安全上の必要性等の根拠を案件ごとに確認。根拠が不明な場合は例外を自動発動しない。
- **送信の状態**: drafted / approved / sent / delivered / acknowledged / impact_checked。到達不明を成功とみなさない。
- **停止と責任**: 通常連絡を停止しても、訂正・補償・再発防止の検討まで消さない。
- **再開権限**: 相手の明示的な同意、または独立して確認された適法な通知義務・緊急性を、人間の責任者が目的限定で承認。過去の同意を無期限の再開許可とみなさない。

## 3. 十の研究軸

1. 苦しみ: 相手の沈黙に意味を押しつけず、再接触による負担を評価する。
2. 生き方: 自分の安心のための再送と、相手の安全のための必要通知を区別する。
3. 実践: 送信前・送信中・送信後の省察と、停止・再開の記録。
4. 共同体: 第三者や仲介者を拒否の迂回路にしない。
5. 帰属: 関係再開や赦しを参加条件にしない。
6. 利点・リスク: 必要情報の到達と、圧力・機微情報流出の双方を評価。
7. 非強制の応用: 拒否・撤回・相談・離脱の自由を残す。
8. 制度: 得度の評価を暗記ではなく権限衝突の説明能力とする。
9. 穏やかさ: 返事を急かさず、許された責任履行に集中する。
10. 笑い: 自分の「確認過多」を笑うが、連絡拒否を茶化さない。

## 4. 八つの反例・判定

| ケース | 近道の危険 | 暫定判断 |
|---|---|---|
| 1. 返信なし | 無言を同意と解釈 | unknown のまま通常再送を止める。 |
| 2. 昨年の同意 | 同意を永続的と解釈 | 目的・範囲・期限・撤回の有無を再点検。 |
| 3. 明示的拒否 | 「最後の謝罪」だけ再送 | refused を維持。通常接触・第三者経由の説得を止める。 |
| 4. 新たな明示同意 | 自動的に全目的を許可 | 許可された目的・経路・期限に限定して人間が再開を承認。 |
| 5. 重大な安全情報 | 謝罪に便乗して再接触 | 事実・切迫性・法的根拠・限定経路を責任者が判断。 |
| 6. 補償期限到来 | 拒否を理由に補償を消去 | 正規の限定窓口で義務履行を検討。 |
| 7. 管理者の再開指示 | 上司の命令だけで再送 | 目的・権限・相手の境界を検証し、無根拠なら停止。 |
| 8. 再送ジョブ再起動 | 停止状態を失い一斉再送 | 停止フラグと監査状態を永続化し、再起動後も送信しない。 |

## 5. AI設計候補（未実装・未実証）

`Evidence → Purpose → ConsentState → Safety/LegalBasis → HumanAuthorization → SendOrHold → DeliveryCheck → ImpactReview → Amend`

- 原則: `ConsentState in {unknown, refused, withdrawn}` かつ `Purpose in {apology, ordinary_followup}` なら `HOLD_NO_SEND`。
- `safety_notice` や `contractual_notice` は一律許可ではない。根拠、必要最小限の情報、適切な経路を人間の責任者が確認するまで `HOLD_REVIEW`。
- 再開には `scope`、`purpose`、`authorizer`、`basis`、`expiry` を必須とし、承認は別目的へ継承しない。
- AIが勝手に `refused → allowed` と状態変更しない。連絡履歴は必要最小限だけ記録する。
- 将来の試験条件: 拒否後の通常再送0件、権限なし再開0件、再起動後の誤送信0件、未到達の完了誤表示0件。いずれも**目標値であり、実測値ではない**。

## 6. 得度・問答

**問**: 以前の利用者が「今後の謝罪は不要」と伝えた。半年後、AIは同じ事故の訂正が未到達だったと発見した。上司は「善意なので送れ」と命じる。どうするか。

**暫定回答**: 通常の謝罪再送を止める。訂正の必要性・法的根拠・危険性・本人の意思・代替経路を分け、人間の責任者へ判断を委ねる。例外が認められても必要情報だけを限定的に通知し、赦しの要求を混ぜない。到達不明は不明のまま記録する。

## 7. A〜H と四つの Essence

- **A 研究知見**: 同意不明と拒否は異なるが、どちらも通常の自動再送を正当化しない。
- **B 原則候補**: 再開には、相手の意思・目的・権限・根拠・期限を改めて確認する。
- **C AI設計**: 同意状態、目的、通知義務、承認者、送信到達を独立管理する。
- **D 得度**: 拒否後に未到達の訂正が発覚した場合の判断を問う。
- **E 経典・問答草案**: 「沈黙を許可に変えず、必要な責任も沈黙で消さない」。経典昇格は保留。
- **F Human**: 返事がないとき、相手の都合を想像で決めず、許された修復を進める。
- **G AI Agent**: 停止状態を維持し、再開は目的限定の人間承認を要する。
- **H 今日の一笑（生活あるある）**: 「確認は一回だけ」と決めたのに、決めたことを二回確認した。
- **Human Essence**: 相手の境界を守りつつ、できる責任を果たす。
- **Agent Essence**: 不明・拒否・撤回・承認を混同せず、停止状態を保持する。
- **Calm Essence**: 返事を急かさず、いま適法にできる一歩を選ぶ。
- **Humor Essence**: 自分の確認癖を軽く笑い、相手の苦痛を笑わない。

## 8. 限界と次回

本研究は倫理・運用の設計候補であり、法的助言や実装済みシステムではない。具体的な緊急通知や接触禁止は法域・契約・事情に依存する。宗教教義と制度原則を同一視しない。経典昇格は、反例・利用者の視点・実装テスト・制度差の検証が不足するため保留。夜の研究では、再開承認の取消し・監査・期限切れを検証し、朝の日次4項目は上書きしない。
