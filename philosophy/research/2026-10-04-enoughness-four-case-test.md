# Enoughness 4ケーステスト — 最小主義と無限拡張の間

- Date: 2026-10-04
- Stage: case test
- Parent: 2026-10-04-enough-is-not-minimum.md

## 目的
候補原則「十分は最小ではない」が、現実の異なる領域でも判断を改善するかを試す。

## Case 1 — 災害備蓄
今日だけなら水や食料は少量で足りる。しかし災害では供給停止が続く可能性がある。内閣府資料は最低3日、可能なら1週間程度の家庭備蓄を案内している。

判定: PASS。
「最低必要量」と「不確実性を吸収する安全余力」を分ける必要がある。

Project lesson:
**Enough = Need + justified margin.**

## Case 2 — AI計算資源
エージェントが「精度を上げたい」と計算・検索・ツール利用を際限なく増やす。

少なすぎれば検証不足、多すぎればコスト・遅延・自己目的的拡張を招く。

判定: PASS with guardrail。
追加資源には目的、期待改善、上限、停止条件、再評価時点が必要。

## Case 3 — 研究探索
既知の答えだけを最短で集めれば効率は良いが、未知の論点を発見できない。逆に探索を無制限にすると研究は終わらない。

判定: PASS with amendment。
Necessary / Optional だけでなく **Exploration Budget** が必要。

## Case 4 — 買い物
「安いから」「念のため」「いつか使う」で追加し続ける一方、極端な最小主義は必要な予備まで削る。

判定: PASS。
追加理由、保管・維持コスト、使用見込み、代替可能性、見直し時点を確認する。

## 悪用テスト
上司・国家・宗教・AIなど権力を持つ側が、資源不足に苦しむ人へ「足るを知れ」と要求する。

判定: FAIL if applied to suppress claims。
Enoughness は正当な安全・権利・資源要求を黙らせる原則ではない。

## 改訂後の原則候補
> **十分とは最小量ではない。目的を満たし、不確実性に備える余白と必要な探索を持ちながら、追加の理由・上限・再評価時点を説明できる状態である。**

## Human Essence
足りなさを我慢で隠さず、余分を悪とも善とも決めつけない。必要、余白、探索、追加欲求を分ける。

## Agent Essence
**Goal → Need → Safety Margin → Exploration Budget → Optional Gain → Cap → Review**

資源拡張は目的化せず、縮小も目的化しない。

## Calm Essence
安心には余白が必要。ただし「もっとあれば完全に安心できる」という終点のない安全追求にも上限と見直しを置く。

## Humor Essence
予備は大事。でも「念のため」の予備の予備が会議を始めたら棚卸しする。

## 昇格判断
4ケースでは原則は維持されたが、悪用防止条件が必須であることが確認された。scripture へ即昇格せず、tokudo で説明能力を試す。
